# 🕐 ПРОБЛЕМА С ЧАСОВЫМИ ПОЯСАМИ И РЕШЕНИЕ

## Проблема

Когда вы создаёте задачи через фронтенд в режиме "human", они могут быть созданы со временем **в прошлом**, потому что:

1. **Фронтенд отправляет время** в локальном часовом поясе клиента
2. **Сервер (AWS) работает в UTC**
3. **Разница часовых поясов приводит к тому**, что `now + смещение` может быть меньше текущего UTC времени

### Пример проблемы:
- Клиент в Армении (GMT+4): 01:00 AM = 21:00 UTC предыдущего дня
- Клиент отправляет: `new Date()` = 2026-01-21T01:00:00 (локальное время)
- Браузер автоматически конвертирует в UTC: 2026-01-20T21:00:00
- Если AWS сервер получает это и добавляет смещение *в UTC*, то может получиться время в прошлом

## Решение

**ВСЕГДА используйте UTC для всех вычислений времени на сервере:**

### 1. В `adsterra/src/lib/adsterra/create-jobs.ts`

❌ **НЕПРАВИЛЬНО:**
```typescript
const now = Date.now(); // Может быть в прошлом из-за часовых поясов
const scheduledTime = new Date(now + baseDelay);
```

✅ **ПРАВИЛЬНО:**
```typescript
const now = new Date(); // Текущее UTC время
const nowUtc = now.getTime(); // Миллисекунды в UTC
const scheduledTime = new Date(nowUtc + baseDelay); // Будущее время в UTC
```

### 2. На фронтенде

❌ **НЕПРАВИЛЬНО:**
```typescript
const startTime = new Date(); // Локальное время
fetch('/api/run', { startTime }); // Отправляет локальное время на сервер
```

✅ **ПРАВИЛЬНО:**
```typescript
const startTime = new Date().toISOString(); // UTC время
fetch('/api/run', { startTime }); // Отправляет UTC время на сервер
```

### 3. На сервере (при получении времени от фронтенда)

✅ **ПРАВИЛЬНО:**
```typescript
// Если фронтенд отправляет ISO строку, конвертируйте в UTC
const startTime = new Date(isoString); // Уже будет в UTC
const nowUtc = new Date().getTime();
if (startTime.getTime() < nowUtc) {
  // Время в прошлом - исправьте!
  startTime = new Date(nowUtc);
}
```

## Текущие файлы, которые нужно исправить

### 1. `adsterra/src/lib/adsterra/create-jobs.ts` (строка 63)
**Проблема:** `const now = Date.now();`
**Решение:** Использовать `new Date()` и всегда работать в UTC

### 2. `src/app/api/adsterra/runs/route.ts` (строка 7)
**Проблема:** Нет валидации времени от фронтенда
**Решение:** Добавить проверку, что время задач не в прошлом

## Как это исправить

1. **Убедитесь, что фронтенд отправляет UTC время**
2. **Убедитесь, что сервер всегда работает с UTC**
3. **Добавьте проверку**: если `scheduledTime < текущее_время`, то установите `scheduledTime = текущее_время`
4. **Тестируйте с разными часовыми поясами**
